## 4. 想定外の結果（そのまま報告する）

### 4.1 「CLTは現金より漏出が小さい」は4ブロック中2ブロックでしか成立しない

厚生等価基準では **B と C でのみ成立**し、A と D では反転する。
等コスト基準では3ブロックで成立するが、**D は両基準で反転**する。

D は建設輸入比率 m_H=0.25、食料輸入比率 m_F=0.30 と最も高い。CLTは建設支出を直接
生むため財政支出の多くが輸入として流出する一方、現金は国内家賃に吸収される割合が高い。
**「CLTは非逃避的」という主張は、建設投入の輸入依存度が低いことを暗黙に前提している。**

これは Phase 1（大域感度分析）の事前予想「支配パラメータは eps_supply と land_share」に対する
反証候補である。少なくともベースラインでは **m_H が符号を決めている可能性が高い**。
Phase 1 で m_H の Sobol 指数を必ず確認すること。

### 4.2 v6の危機指標の大部分は基軸国の逃避流入による測定上の産物

`reserve_flight_mode=off` にすると：

| シナリオ | A severity (v6 → off) | B severity (v6 → off) |
|---|---|---|
| welfare:ubi | 10.368 → **1.092** | 3.424 → 3.434 |
| welfare:cash_t | 0.404 → **0.000** | — |
| cost:clt | 14.035 → **3.693** | 5.032 → 5.041 |

- **小さい給付（厚生等価の cash_t / voucher）では危機が完全に消える。** 全てが産物だった。
- **大きい給付では残る。** ただし残るのは主に **B** の危機で、B は逃避流入の影響を
  ほとんど受けない（3.424 → 3.434）。A の severity は約9割が産物。
- v6でのAの為替は30年後に **e = 0.171**（83%の増価）。これは `app` 閾値 0.3 を大きく割り込む。

**したがって v6 の「危機カウント」を単一の数値として報告してはならない。**
産物（A の増価）と実体（B の債務・FX動学）が混在している。

### 4.3 比較基準によって結論が変わる

A は厚生等価では反転（+0.017）、等コストでは成立（−0.023）。
**どちらか一方だけを報告すると結論が変わる。** 両基準の併記を維持すべき。

## 5. 設計判断（仕様が曖昧だった箇所）

1. **`capped` モードの実装**：為替に下限 `reserve_flight_floor`（既定0.3）を課す形にした。
   流入自体は残すが、増価だけでは危機が発生しないようにする。`off` は流入を完全に除去する。
   両方を用意したのは、「流入が無い世界」と「流入はあるが増価が青天井でない世界」が
   別の反実仮想だからである。
2. **設定ファイルのパーサ**：`model/` の標準ライブラリ制約を `run_all.py` にも広げ、
   PyYAML依存を避けて簡易パーサを書いた。フラットな `key: value` のみ対応。
   Phase 1 で入れ子構造が必要になれば PyYAML を `analysis` 依存に追加する。
3. **回帰テストの方式**：スナップショット比較ではなく `legacy/sim_v6.py` をその場で実行して
   比較する方式にした。スナップショットは生成時点の誤りを固定してしまうため。
4. **`universal_split`**：既定を `None` とし、`c_pop_share` にフォールバックする。
   v6 の挙動を保ちつつ「人口比＝配分比」という暗黙の同一視を切り離した。
5. **findings テストの追加**：TASKS.md には無いが、4節の反転を `test_phase0_findings.py` に
   固定した。CLAUDE.md の「不都合な結果もそのまま報告する」を後続フェーズで
   機械的に担保するため。

## 6. 次フェーズに影響する設計判断

- **Phase 1 の振るパラメータに m_H を単独で入れるべき**。TASKS.md では m_F, m_G, m_H を
  一律倍率で振る設計だが、4.1 の結果から m_H が符号を支配している可能性がある。
  一律倍率だと m_H 単独の寄与が Sobol 指数で分離できない。
  **提案：m_H を独立ブロックとして振る**（他の輸入比率とは別倍率）。
- **Phase 1 の報告は基準別（厚生等価／等コスト）に分ける必要がある**。4.3 のとおり
  基準で符号が変わるため、統合した成立割合は誤解を招く。
- **Phase 4 の危機指標は `reserve_flight_mode` を明示する必要がある**。4.2 のとおり
  v6既定では A の危機がほぼ全て産物。Phase 4 のモンテカルロは `capped` か `off` を
  主系列にし、`v6` を対照として併記するのが妥当と考える。
